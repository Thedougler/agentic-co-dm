## Project — vault/ (governed wiki pages)

Core system references: `vault/srd/rules/character-creation.md`,
`vault/srd/rules/monsters-overview.md`, `vault/srd/rules/spells-overview.md`,
`vault/srd/rules/rules-glossary.md`.

1. **Campaign state files** — seven files orient agents and prevent re-derivation: `index.md` (wiki map), `hot.md` (recent changes), and per-campaign `vault/campaigns/shattered-sea/campaign-overview.md` (campaign identity, truths, tone), `vault/campaigns/shattered-sea/threads.md` (active narrative pressure), `vault/campaigns/shattered-sea/spoilers.md` (DM-only secrets), `vault/campaigns/shattered-sea/player-gravity.md` (player gravity), `vault/campaigns/shattered-sea/party-items.md` (party inventory). Read triggers and update rules live in `CLAUDE.md`'s project section. Campaign overview is owned by `draft-content/references/campaign.md`; threads and spoilers are owned by `world-update`; party items update when a PC inventory changes.

2. Canon is simple: **played at the table = `status: canon` in frontmatter, edits additive-only** — never contradict or delete a played fact; **not yet played = `status: pending`, edit freely, no gate**; **imported 5e SRD reference material = `status: srd`, sourced not played, edit freely to correct transcription errors**. Canon state lives in frontmatter ONLY — prose states facts plainly, no provenance narration, no ruling quotes, no "as of session N" (git log is the history).
3. Publishing is default-deny. NEVER set `publish: true` on a page the user hasn't approved for players — list it in the publish proposal instead (L3).
4. NEVER create a wiki page freeform — instantiate the matching template from `vault/_templates/` (L4); no matching template exists → chain-load content-type-scaffold first.
5. `vault/_templates/` is sole formatting authority for vault/ — pattern absent from template = strip from every file, no exceptions, no asking, however common (precedent isn't evidence).
6. "Repo convention" / "existing convention" / "how the wiki already does it" is not a thing for vault/ — only `vault/_templates/` codifies convention (precedent that outran the template is an error, not a pattern to honor).
7. Sweeping a rule-5 removal: add the dropped pattern to W34's STALE_PATTERNS (`docs/vale-styles/CampaignOS/StalePattern.yml`'s `swap:` map), then dispatch `content-fixer` per flagged file — 3+ files → one background Agent batch (PJ15) — the linter tracks the sweep to 0, not your grep.
8. Each fact lives on exactly one page. A verbatim-repeated block (must read identically at every site) collapses to a `![[page#Heading]]` transclusion of the owning page's section; a fact restated in different words collapses to a `[[wikilink]]` to the owning page. Rot (structural or duplicate) → fix per docs/guardrails/PROJECT.md PJ11.
9. Pending content NEVER appears in recaps or the site; INGEST promotes what actually hit the table.
10. Creative work (governed .md prose in vault/**, including its vault/campaigns/shattered-sea/pcs/ and vault/episodes/ subtrees): CLAUDE.md rule 1 plus rules 2-9 above bind facts, canon, structure, visibility — never style. Kit CODE/PLAN/VERIFY routing + iron rules don't bind it either — read docs/guardrails/PROJECT.md. Invent boldly inside these rails; a timid minimum-risk draft violates this rule. Style means voice, structure, imagery, risk — never register: the weight of what happens on the page is a fact of the material, and a charged beat written light violates this rule the same way a timid draft does (`vault/refs/stories/register.md`).

- About to edit any file under vault/ → read `vault/refs/runbook-wiki.md`
- About to write a callout (`> [!`), a DC/skill check, a DM secret, or a hazard on a wiki page → load callouts
- About to draft or revise campaign prose beyond a sentence (lore, quest text, NPC dialogue, handout, recap draft, or any story on the shelf under vault/stories/ — including fixing its pacing, beats, or a sagging middle) → Read docs/guardrails/STORY.md, then chain-load draft-story (its DS3 emits the `REGISTER:` line before the first sentence)
- About to create or expand a page under any drafted type (npc/location/faction/item/monster/ship/encounter/quest/lore/rumour/rule/campaign/season/handout/puzzle/table/background/species/feat/event/secret/deity/culture/calendar/threat/condition/document/material/profession/route/class/spell/world) → Read docs/guardrails/CONTENT.md, then chain-load draft-content for the owning guide
- About to design travel events, a journey leg, or what happens on a crossing/voyage the party will play → chain-load travel-events (events derive from the party's own threads — never rolled from a route page's encounter table)
- About to finish creating or editing a vault/** file (incl. the vendored SRD/craft reference material under it) → run `npm run lint -- <path>` yourself and fix any finding now, same turn, never NOTED (not done) (docs/guardrails/PROJECT.md PJ15)
- About to hand-fix the same content defect a 2nd time, OR about to grep/sweep the repo for an old key, path, name, or shape (any migration/rename) → BEFORE fixing any page, add the old shape to W34's STALE_PATTERNS (`docs/vale-styles/CampaignOS/StalePattern.yml`'s `swap:` map) or a new rule (`utils/wiki-cli/src/wiki_cli/rules/`) — the linter, not your grep, tracks the sweep to 0
