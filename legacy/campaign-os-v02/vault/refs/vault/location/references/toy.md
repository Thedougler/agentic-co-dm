# Location Toy Chest (four fields)

Write these once, as a markdown table in the DM-only material. No
frontmatter duplication — these are prose fields with no machine-readable
payoff a second YAML copy would earn. Distinct from
`vault/refs/vault/npc/references/toy.md`'s five fields — a location's Toy
Chest is four fields, not the NPC's five.

| Field | Content |
|---|---|
| `verb` | What this location *does* — its active principle, even untouched. One of: **Defend**, **Attract**, **Consume**, **Conceal**. |
| `unstable_condition` | Concrete state, not a vibe. |
| `consequence` | What happens if no one intervenes — observable, specific. |
| `link_of_relevance` | The PC-Connection Requirement — which PC, and the specific mechanism. Required, wikilinked. |

**Verb vocabulary:**

| Verb | Meaning |
|---|---|
| **Defend** | Walls, checkpoints, secrets kept in |
| **Attract** | Draws people, resources, or danger toward it |
| **Consume** | Takes things in and changes them |
| **Conceal** | Hides something; the location exists to keep a secret |

- `unstable_condition` — ✓ "The east gate guard rotation has a two-minute
  gap no one has officially reported." ✗ "Tensions are high and the guards
  are on edge."
- `consequence` — ✓ "The gap gets noticed and filled permanently within
  three days." ✗ "Things will get worse."
- `link_of_relevance` — if you can't answer this in one sentence, the
  location isn't ready to generate.
