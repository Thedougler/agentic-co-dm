# Audit and revise

Run the audit after the reference gate and again after playtest. Mark each item pass, concern, or fail. Fix the smallest rule that restores the intended decision loop; do not add another feature to hide a problem.

## Mechanical audit
### Identity and usability
- [ ] One-sentence fantasy, role, signature, goal, fear, counterplay, and proof are present.
- [ ] The first turn demonstrates the role; every printed option has a reason to exist.
- [ ] Tell → Threat → Responses → Payoff is explicit for each signature feature.
- [ ] Range, area, targets, timing, duration, recharge, resource cost, attack bonus, and DC are complete.
- [ ] Notation is current; any 2014 conversion is labeled.

### Chassis and offense
- [ ] Rank/CR, PB, AC, HP, attack/DC, damage, speed, saves, and skills were compared with two peers.
- [ ] Three-round script includes likely target count, misses, saves, resistance, recharge, setup, reactions, off-turn actions, and ally enablement.
- [ ] Routine DPR and burst/area/control are separate; no ideal maximum target assumption is doing all the work.
- [ ] Action economy is plausible for the rank; solo pressure comes from choices and off-turn play, not only inflated numbers.
- [ ] Damage/control/defense trade rules were applied; strong axes have a weakness or cost.

### Defense and counterplay
- [ ] Effective HP includes only relevant resistance, regeneration, healing, avoidance, cover, and immunity effects once.
- [ ] Saves and immunities do not blank the party toolkit without a bypass or alternative target.
- [ ] Hard conditions have a clear save/repeat/escape and do not delete turns repeatedly.
- [ ] Mobility, escape, stealth, and reactions have tells and limits.
- [ ] Lightning rods, terrain, or allies provide meaningful non-body targets.
- [ ] Traps and signature threats have at least two ways to discover, avoid, interrupt, or recover.

### Encounter and table test
- [ ] Starting position, allies, terrain, reinforcement/escape logic, and failure state are specified.
- [ ] The DM can run the first three rounds without hidden math.
- [ ] The monster remains interesting when its signature is countered.
- [ ] Expected player answers are fun, visible, and not dependent on one character or one check.

## Playtest failure → correction
| Failure observed | Smallest correction first |
|---|---|
| Players cannot tell what matters | Add a visible tell and state the threat; remove a competing trait. |
| Monster is a bag of hit points | Lower HP, add a lightning rod/phase, and give the arena a choice. |
| Monster dies before signature appears | Move setup to a trait/reaction, improve position, or shorten recharge; do not blindly add damage. |
| Monster dominates round 1 | Remove a rider, reduce target count, add a telegraph, or make setup cost an action. |
| DPR too high after misses/resistance are modeled | Cut one attack/rider, reduce frequency, or trade damage for mobility/control. |
| DPR too low or choices are inert | Increase reliability modestly, add a useful setup/payoff, or remove a dead option. |
| AC/defenses cause whiffs | Lower AC or narrow the defense; preserve HP only if the trade is intentional. |
| Resistance/immunity blanks a character | Narrow it, make it temporary/bypassable, or add a second target/objective. |
| Hard condition feels like turn deletion | Use a repeat save, shorter duration, partial effect, movement/resource pressure, or a visible interrupt. |
| Solo feels like a single bag of stats | Add reliable off-turn movement/setup, phase choices, and a lightning rod; rerun budget. |
| Players miss a trap because of one check | Add a tell, alternate route, costed disarm, and recoverable failure. |
| Boss phase feels arbitrary | Telegraph the threshold and define the changed decision loop and player response. |
| 2014 conversion feels off | Keep the fiction, recalculate current attack/DC, HP/AC, damage, and action economy; relabel confidence. |
| Stat block is slow to run | Delete options, consolidate repeated text, and fill Running the Monster fields. |

## Revision loop
1. Name the observed failure and intended player decision.
2. Identify whether the fault is fiction, role, action economy, offense, defense, counterplay, or encounter context.
3. Change one lever; rerun the three-round and defense audits.
4. Test a normal party response and the strongest obvious counter.
5. Keep the revision only if it improves the decision loop without stacking defenses or turn denial.
