# Contract: Sequential ingest

The interface is ingest or promote of one or more approved source files. Co-DM is the writer. Players never open the pages.

## Sequential unit

1. One input file is `open` at a time.
2. Do not create or change wiki pages for a later file, and do not update tracking for a later file, while an earlier file is `open`.
3. Completing a file means: required pages filed or stubbed, tracking updated, file marked `complete` or `failed`.
4. Folder size, batch size, and a request for speed do not authorize overlap.
5. A failed file is closed with a reason before the next file starts. Remaining files still run, sequentially.

## Quality bar

6. Incoming files are evidence of facts. They are not exemplary page format.
7. A filed wiki page matches the campaign kind for its subject and answers that kind’s jobs (`wiki/AGENTS.md` Layout).
8. Do not copy a foreign outline, heading list, or density band as the wiki page shape.
9. A source that already matches a campaign kind is still judged against that kind’s jobs and required treatments.
10. Campaign-shaped session-prep and place keep 007/008 required treatments (session-prep body; place `[!narration]`). Foreign sources of those subjects map into the kind; they are not photocopied.

## Report

11. After a multi-file ingest, report each file in processing order: complete or failed, pages produced or updated, failure reason.
12. A later update to an earlier page is attributed to the later file.

## Gates

13. Unaccepted Work does not publish, except named ingest of approved sources.
14. Invented names are Work.
15. Numbers live on one owner page.
16. Spoken look is theatre of the mind.
17. Legacy pages not in the ingest are not restyled solely for this feature.

## Out of contract

Foundry staging. Player-facing sheets. Inventing new campaign types. Trading quality for batch speed.
